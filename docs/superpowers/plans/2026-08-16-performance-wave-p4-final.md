# Performance Wave P4 Final Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the performance pass with allocation/CPU fixes that preserve behavior exactly and make Macrobenchmark/Baseline Profile journeys deterministic without manual seed data.

**Architecture:** Reader hashing becomes incremental, chapter candidate selection becomes single-pass, and benchmark-only source code owns a deterministic local fixture. Production startup remains unchanged; startup/frame/memory measurement is expanded in `:benchmark` instead of adding speculative runtime work.

**Tech Stack:** Kotlin 2.4.10, AGP 9.3.0, AndroidX Benchmark 1.5.0-beta01, Compose BOM 2026.06.00, Room 2.8.4, Hilt, coroutines.

## Global Constraints

- Use the uploaded P3-verified ZIP as the exact baseline.
- Preserve Reader document validation, block IDs, and fingerprints byte-for-byte.
- Preserve chapter aggregation links/reviews/tombstones and deterministic tie-breaking.
- No Room schema migration.
- No production UI/visual behavior change.
- Benchmark fixture code must exist only in the `benchmarkRelease` source set/manifest.
- Keep frame timing metrics separate from memory metrics to avoid self-induced measurement overhead.

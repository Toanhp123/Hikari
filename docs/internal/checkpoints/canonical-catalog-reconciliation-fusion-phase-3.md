## Represented implementation boundary

### Task 22 — reconciliation domain and StoryId compatibility

- Adds versioned `ReconciliationPolicy` v1 with the normative 0.92 / 0.75 / 0.50 / 0.05 thresholds.
- Adds canonical unordered case keys, semantic decisions, merge eligibility, bounded reason-code vocabulary, symmetric evidence and assessments.
- `ReconciliationEvidenceFactory` converts persisted `CatalogSourceRecord` identity facts and normalizes incoming facts with the existing `TitleNormalizer`.
- `CatalogStoryIdFactory` preserves the legacy deterministic semantic StoryId inputs and uses monotonic numeric suffixes only on actual collisions.

### Task 23 — candidate discovery and observe-only assessment

- Adds a high-recall in-memory candidate index using durable source ownership, WORK identifiers, normalized title tokens and authors for retrieval only.
- `CatalogReconciliationEngine` applies hard content/lineage/WORK-identifier conflict gates before title/author similarity and enforces the minimum winning lead.
- Candidate evidence from multiple sources is collapsed per Story before winning-lead comparison.
- `CatalogIngestReconciliationIndex` gives known `SourceKey` ownership absolute precedence, supports local forks, and returns DIRECT_OWNER/AUTO_LINK/CREATE_FOR_REVIEW/CREATE_SEPARATE without graph mutation.

### Task 24 — durable cases and observe-only reconciliation service

- Adds `ReconciliationCaseRepository` and `CatalogReconciliationService` without any merge-executor dependency.
- Adds `RoomReconciliationCaseRepository` over the existing schema-9 case/revision tables; no `9 -> 10` migration is introduced.
- Identical evidence + policy is revision-suppressed; durable separation is preserved for identical evidence; changed identity fingerprint or policy version can create a new assessment revision.
- REVIEW persists one active durable case; DIFFERENT_WORK persists an engine-resolved separation; SAME_WORK is recorded as observe-only evidence and returns `AutoMergeObserved`; NO_MATCH creates no case.
- Candidate-index global rebuild is lazy/invalidation-driven rather than rebuilt on every reconciliation call.

### Task 25 — persisted change facts and runtime ingest cutover

- `CatalogRepository` commit APIs now return persisted `CatalogCommitChange` facts with independent identity/fusion fingerprint-change flags.
- Room computes those flags from committed before/after `CatalogSourceRecord` state. Timestamp-only Summary refresh does not become semantic identity/fusion churn.
- Home/Search/unowned Details use reconciliation ingest evidence instead of runtime `StoryMatcher`/legacy `CatalogMatchIndex`. Legacy matcher code remains for characterization only.
- Known `SourceKey` always follows its durable owner. Unowned compatible evidence can AUTO_LINK before commit; REVIEW/NO_MATCH/DIFFERENT_WORK creates a deterministic host Story before persistence and never performs a destructive merge.
- Home/Search use fork/commit discipline. After commit, returned durable ownership is applied to the fork before promotion so a concurrent/durable owner can override the temporary proposal without poisoning the parent ingest context.
- Existing-owner richer Full metadata still routes an identity-fingerprint change through observe-only reconciliation, covering the retroactive-link case.
- Identity change temporarily routes directly to `CatalogReconciliationService`; fusion change routes to `CanonicalGenerationRebuilder`. Neither path fetches provider/network data.
- Adversarial fixtures cover content-type conflicts, sequel-like titles, shared/conflicting WORK identifiers, transliteration, missing authors, provider-record identifiers, close candidates inside the 0.05 lead, and provider-order permutation.

## Explicit non-claims

This patch does **not** implement or enable:

- Task 26 survivor/user-state-footprint policy;
- destructive/atomic Story graph merge, redirects generated by a new merge, merge reversal, or merge executor behavior;
- user reconciliation Review UI or protected-state conflict resolution;
- WorkManager/background reconciliation orchestration;
- a Room migration beyond schema 9;
- provider-ID priority branches, plugin-declared trust/confidence, or network fetching inside reconciliation/fusion reasoning.

`AutoMergeObserved` is observation/audit output only. It is not a graph mutation request.

- feature error-path fixtures were moved from the retired `matchSnapshot()` boundary to the Phase-3 `sourceRecords()` boundary;

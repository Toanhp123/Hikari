# External catalog

Catalog discovery and search are read-only. Each `CatalogEntry` has an opaque, provider-qualified `CatalogEntryId`; it is normalized summary metadata, not `Media`, `SourceMediaRef`, a source registry entry, library content, or playable/readable capability. Rich fields that are only needed after navigation live on `CatalogEntryDetails`; `CatalogEntry` keeps the summary/hero fields used by discovery and search. AniList supplies Home discovery, the primary Search destination, and details. For manga and light novels without a saved source association, Read first asks for one compatible installed source, then resolves the catalog title and known aliases against only that source. The picker exposes one scrollable language menu when at least two concrete provider-reported languages exist. All-language and unspecified variants are not concrete filter choices. In the All view, variants collapse only when opaque presentation identity and clean display name agree and every concrete language is distinct; choosing that row opens language selection inside the same adaptive picker. Ambiguous variants stay separate. A concrete filter searches exactly its visible source IDs and excludes local scanning; All leaves source IDs unrestricted and retains local scanning. Every Catalog-originated Source Search fixes the originating media type, hides type chips, and displays its language or selected-source scope. A single normalized exact match selects its source-owned chapter list inside Catalog Detail; ambiguous or missing matches require explicit confirmation or source-scoped manual search. Contextual Source Search returns the selected media and its own preview metadata to Catalog, never a Source Detail route. Standalone Source Search and source-only Library retain native detail navigation. Anime keeps the existing title-seeded source-search path until Hikari has a matching remote anime source capability. A real source result is still required before content opens.

Progress, Library, and remote series continuation remain independent. Direct-media Home Continue joins incomplete progress records to saved Library entries by exact source reference. For remote manga/novels, Continue joins saved series relationships to the exact chapter progress, including completed chapters; resume requires an available source and opens the saved chapter with an optional validated cached canonical sequence. Sequence refresh is independent from reader opening, including on cache miss. Chapter identity is never inferred from title or chapter number.

## Unified reading navigation

Catalog Detail defaults to Information. Loading Information never searches content sources or loads source details. Read selects Chapters, restores the saved source association and prompts for a source only when none is selected. Chapter search/filter, display reversal and per-tab scroll positions remain route-local; cancel leaves the previous selection intact. The cinematic hero is shared above the Material tabs; a nested scrolling header stays collapsed across tab switches while each tab retains its own position. Chapter rows remain lazy. Selecting a chapter opens Reader directly with the complete immutable canonical source sequence, not the filtered/reversed display list. Reader Back refreshes only the selected-source continuation target, not catalog metadata or chapter details. A continuation marker identifies the saved reading target; per-chapter completion badges are not inferred from that single reference.

`CatalogDetailViewModel` owns catalog metadata only. `CatalogChaptersViewModel` independently coordinates source selection, snapshot freshness and the existing reading-target workflow. Chapter rows, controls and primary reading CTA reuse source-native presentation. Confirmed source associations are durable in `UserDatabase`, keyed by exact `CatalogEntryId` provider/value plus media type and storing the exact source reference, candidate title and type. Saves are queued in confirmation order, survive route disposal and are not awaited before chapter loading; saved associations restore after route disposal or app restart. Changing an association does not migrate progress or Library. No fuzzy identity, merged chapter list or catalog identity in source progress is introduced. Selected-source Library uses only source media and source artwork; AniList artwork is never substituted.

Phase 5.1 chapter snapshots are a separate disposable cache, not durable source associations or user progress. Catalog reads validated chapter snapshots before requiring an available source or acquiring a media lease. A snapshot younger than one hour avoids source details; stale data displays immediately while revalidating. Explicit refresh always attempts the source and retains a valid list on error. Cache miss/corruption/eviction uses normal source loading. Source display order is recorded separately from canonical reader order; see ADR-024 for legacy snapshots.

Each source detail load acquires `OpenMedia` ownership locally and releases it after that operation settles, even after selection replacement or disposal. Reader opening acquires its own selected-source lease; dismissal returns promptly, but release waits for owned adjacent/page/content/resource/prefetch work to settle. Generations reject stale selection, loading, reader navigation and error publication, including A/B/A identity changes. Direct local manga/publication candidates stay selected in Catalog and use the native direct-reader workflow without visiting Source Detail.

Catalog providers are composed separately from `SourceRegistry`. AniList provider owns its HTTP client when default-composed and is closed by `AppDependencies`; injected providers are caller-owned unless ownership is explicitly transferred.

GraphQL discovery batches bounded sections in one request to respect AniList rate limits. Featured is a balanced spotlight built from separate trending Anime, Manga, and Light Novel candidate pools, capped equally per media type and interleaved without a custom cross-type score. Partial sections and details remain visible with warnings when valid response data exists. A detail response with no media and GraphQL errors is a retryable failure, not a missing entry. Discovery queries exclude adult media.

The primary Search destination searches catalog metadata, not extension/local content. Source Search is a secondary discovery/recovery surface. Catalog Detail normally resolves manga/light-novel content in context after explicit source selection; Source Search is shown only when the user asks to search all sources or when automatic resolution needs manual correction. This keeps discovery identity separate from content-source identity.
